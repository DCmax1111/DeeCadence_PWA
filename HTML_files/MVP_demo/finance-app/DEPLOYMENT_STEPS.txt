================================================================================
                        DEECASH DEPLOYMENT GUIDE
                  Step-by-Step: Repo Setup to Production
================================================================================

OVERVIEW
--------
This guide walks you through:
1. Creating a GitHub repository (or using existing)
2. Setting up DeeCash locally with Supabase
3. Deploying to Vercel with secure secrets management

Total time: ~30 minutes (most is waiting for services to initialize)

================================================================================
PHASE 1: GITHUB SETUP
================================================================================

STEP 1: Create a GitHub Repository (if new)

1a. Go to https://github.com/new
1b. Repository name: "deecash" (or your preference)
1c. Description: "DeeCash — Finance bookkeeping app"
1d. Visibility: Private (recommended for now)
1e. Click "Create repository"
1f. Note the HTTPS URL: https://github.com/YOUR_USERNAME/deecash.git
 
STEP 2: Initialize Git locally

2a. Open PowerShell and navigate to the DeeCash app:
    $ cd "HTML files/MVP demo/finance-app"

2b. Initialize git repo:
    $ git init
    $ git add .
    $ git commit -m "Initial DeeCash app scaffold"

2c. Add remote and push:
    $ git remote add origin https://github.com/YOUR_USERNAME/deecash.git
    $ git branch -M main
    $ git push -u origin main

2d. Verify on GitHub: Go to your repo URL and confirm files are visible

IMPORTANT SECURITY CHECK:
    $ git check-ignore .env.local
    Expected output: .env.local
    (If no output, .env.local might be committed — fix it before proceeding!)

================================================================================
PHASE 2: LOCAL SETUP WITH SUPABASE
================================================================================

STEP 3: Create Supabase Project

3a. Go to https://app.supabase.com
3b. Click "New Project"
3c. Organization: (select existing or create new)
3d. Project name: "deecash-prod" (or staging variant)
3e. Database password: Generate strong password (save securely!)
3f. Region: Pick closest to your market (us-east-1, eu-west-1, etc.)
3g. Click "Create new project" (wait ~2 minutes)

3h. Once ready, go to Settings > API
    Copy these three values:
    - Project URL (NEXT_PUBLIC_SUPABASE_URL)
    - Anon Public Key (NEXT_PUBLIC_SUPABASE_ANON_KEY)
    - Service Role Key (SUPABASE_SERVICE_ROLE_KEY — keep secret!)

STEP 4: Create Database Tables

4a. In Supabase, go to SQL Editor
4b. Create new query
4c. Open file: "HTML files/MVP demo/SCHEMA.sql"
4d. Copy entire contents
4e. Paste into Supabase SQL Editor
4f. Click "RUN" button
4g. Wait for success message (green checkmark)

Verify tables were created:
    Go to Supabase > Database > Tables
    You should see: profiles, ledger_entries, subscriptions, transactions, etc.

STEP 5: Configure Auth URLs

5a. In Supabase, go to Authentication > URL Configuration
5b. Site URL: http://localhost:3001
5c. Redirect URLs: http://localhost:3001/auth/callback
5d. Save

STEP 6: Set up Local Environment

6a. In PowerShell, navigate to DeeCash:
    $ cd "HTML files/MVP demo/finance-app"

6b. Copy environment template:
    $ cp .env.local.example .env.local

6c. Edit .env.local (use VS Code or Notepad):
    $ code .env.local

6d. Fill in values (from Supabase step 3h):
    NEXT_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
    NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
    SUPABASE_SERVICE_ROLE_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
    NEXT_PUBLIC_APP_URL=http://localhost:3001

6e. Save and close

STEP 7: Install Dependencies

7a. In PowerShell (in finance-app folder):
    $ npm install

    (This installs Next.js, Supabase client, axios, and other packages)
    (Takes 2-5 minutes depending on internet speed)

7b. Verify success: Look for "added XX packages" message

STEP 8: Test Locally

8a. Start dev server:
    $ npm run dev

    Expected output:
    > deecash@0.1.0 dev
    > next dev -p 3001
    ▲ Next.js 14.1.0
    Local:        http://localhost:3001

8b. Open http://localhost:3001 in your browser
8c. You should see DeeCash login page
8d. Test: Click "Sign in" → Sign in with Google (or create email account)
8e. Once logged in, go to /ledger and create a test entry
8f. Stop server: Press Ctrl+C in PowerShell

SUCCESS: DeeCash is working locally with live Supabase data!

================================================================================
PHASE 3: DEPLOY TO VERCEL
================================================================================

STEP 9: Create Vercel Project

9a. Go to https://vercel.com
9b. Sign up or log in (use GitHub for easiest flow)
9c. Click "Add New" > "Project"
9d. Find your GitHub repo ("deecash") and click "Import"
9e. Framework: Next.js (auto-detected)
9f. Root Directory: "HTML files/MVP demo/finance-app"
    (This is the relative path from your repo root — adjust if structure differs)
9g. Click "Deploy"

    Vercel will:
    - Clone your repo
    - Run npm install
    - Build the app
    - Deploy to edge network

    (Takes 2-5 minutes)

9h. Once deployed, click on the deployment URL (e.g., deecash.vercel.app)
    Note: App will NOT work yet — missing environment variables!

STEP 10: Add Environment Variables in Vercel

10a. In Vercel project, go to Settings > Environment Variables
10b. Add each variable below:

    NEXT_PUBLIC_SUPABASE_URL
    Value: https://YOUR_PROJECT.supabase.co
    Environments: Production, Preview, Development

    NEXT_PUBLIC_SUPABASE_ANON_KEY
    Value: eyJhbGc... (from Supabase dashboard)
    Environments: Production, Preview, Development

    SUPABASE_SERVICE_ROLE_KEY
    Value: eyJhbGc... (from Supabase dashboard)
    Environments: Production ONLY (secret — not in Preview/Development)

    NEXT_PUBLIC_APP_URL
    Value: https://YOUR_VERCEL_DOMAIN.vercel.app
    Environments: Production, Preview, Development

10c. Optional: Add payment provider keys (when ready)
    CLEVA_API_KEY, CLEVA_WEBHOOK_SECRET
    MONIEPOINT_API_KEY, MONIEPOINT_WEBHOOK_SECRET
    PALMPAY_API_KEY, PALMPAY_WEBHOOK_SECRET
    (All set to Production only until ready to test)

10d. Click "Save" after each variable

STEP 11: Update Supabase Auth URLs (for Production)

11a. In Supabase, go to Authentication > URL Configuration
11b. Site URL: https://YOUR_VERCEL_DOMAIN.vercel.app
11c. Redirect URLs: https://YOUR_VERCEL_DOMAIN.vercel.app/auth/callback
11d. Save

STEP 12: Redeploy to Vercel

12a. In Vercel, go to Deployments
12b. Click the latest deployment > "Redeploy"
    (This picks up the new environment variables)

12c. Wait for green checkmark
12d. Click on the deployment URL

STEP 13: Test Production

13a. Go to your Vercel URL (e.g., https://deecash.vercel.app)
13b. Test sign up/sign in
13c. Create a test ledger entry
13d. Verify data appears in Supabase (Supabase > Table Editor > ledger_entries)

SUCCESS: DeeCash is live in production with Supabase backing!

================================================================================
PHASE 4: ONGOING UPDATES
================================================================================

STEP 14: Make Code Changes

14a. Locally, make changes to pages/, components/, etc.
14b. Commit and push:
    $ git add .
    $ git commit -m "Feature: add export functionality"
    $ git push origin main

14c. Vercel auto-detects the push and redeploys automatically
14d. Check Vercel Deployments for live status

STEP 15: Update Secrets (Payments, API Keys)

15a. If you need to change environment variables:
    - Update Vercel Environment Variables (don't commit to Git!)
    - Click "Redeploy" in Vercel to apply changes
    - No Git push needed for secret updates

STEP 16: Monitor and Debug

16a. View logs in Vercel:
    Deployments > [Latest] > Logs tab
    Shows build output and any errors

16b. Monitor errors:
    Vercel > Analytics > Error Tracking
    See real-time errors from production users

================================================================================
TROUBLESHOOTING
================================================================================

PROBLEM: "npm install" fails locally
SOLUTION:
  $ npm cache clean --force
  $ npm install

PROBLEM: "npm run dev" gives port 3001 already in use
SOLUTION: Either:
  a) Kill the process: taskkill /PID [process-id] /F
  b) Use different port: npm run dev -- -p 3002

PROBLEM: Sign-in redirects don't work locally
SOLUTION:
  Check Supabase > Auth > URL Configuration has:
  - Site URL: http://localhost:3001
  - Redirect URL: http://localhost:3001/auth/callback

PROBLEM: Vercel deployment fails during build
SOLUTION:
  1. Run locally: npm run build (to test build)
  2. Check output for errors
  3. If it's a missing dependency, add to package.json and push
  4. Vercel will retry automatically

PROBLEM: Ledger entries not persisting after sign out
SOLUTION:
  Ensure RLS (Row-Level Security) policies are enabled in Supabase
  Check: SQL Editor > Run:
    SELECT schemaname, tablename FROM information_schema.tables
    WHERE schemaname='public'
    AND tablename='ledger_entries';
  
  If RLS is off, enable it:
    ALTER TABLE ledger_entries ENABLE ROW LEVEL SECURITY;

PROBLEM: ".env.local" appears in Git history (accidentally committed)
SOLUTION:
  1. Immediately rotate all Supabase and payment keys
  2. Remove from Git history:
     $ git filter-branch --tree-filter 'rm -f .env.local' HEAD
     $ git push --force-with-lease
  3. Update Vercel environment variables with new keys
